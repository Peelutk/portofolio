HISADA

An administration system for the student council (Himpunan Santri) at Daarul Uluum Lido Islamic Boarding School. The focus of this project was to design the system properly before writing any code.

problem

Student administration was spread across many hands.

[ISI: describe the situation before HISADA. Example: attendance, leave permits, health, and discipline were recorded separately by different student officers, so records were hard to trace and every change of officers left data scattered.]

process

Five stages, in order.

  1. Mind map

    Mapped every administrative function of the school into one tree. [ISI: detail]

  2. Analysis

    Audited the old system, then numbered every design decision (K-01, K-02, …) so each one could be traced. [ISI: detail]

  3. Flowcharts

    Drew flows such as leave permits and officer handover as Mermaid diagrams. [ISI: detail]

  4. Database design

    Defined tables and relations, including change history and separate data for boys' and girls' campuses. [ISI: detail]

  5. Coding

    Built a web prototype with sample data for future users to try. [ISI: detail]

outcome

An agreed design and a prototype anyone can try.

  • More than a hundred design decisions recorded with their reasons.
  • Role-based access, with boys' and girls' data kept separate.
  • A web prototype that can be explored from the point of view of each role. [ISI: prototype link, if you want to share it]

What I learned.
